# 真正的 LSP 导航与生命周期

目标：在“全部 DSH 能力”目标下装配官方 RC.4 lsp／lsp-stdio／tool-lsp，通过现有公共 subprocess provider 运行真正的 TypeScript language server，补齐四种语义导航。不得用 grep、固定 JSON 或电脑代执行冒充语言服务器。

基线：`2285a0b4bbabfc363ffbe1d7132b0a330ad7a27c`，`codex/harmonyos-package-management`，工作树干净；普通 0.4.34 已安装到 Phone 模拟器，公共进程／路径基础已验。继续在 Mobile Harness 仓库，不修改 SayAct。

实现：DSH 三个包沿现有子模块 RC.4 和精确 npm 锁文件；独立语言服务器、TypeScript 使用标准源码 submodule 锁定发布提交，运行时用匹配的精确生产包。正常 mobile profile 组合官方插件，按需启动 JS／TS 服务器；恢复模式不启用。服务器配置、工具、文件读取和结果渲染复用上游扩展点，不修改核心。明确配对 Host 原生路径与 Guest 进程视图。

验收：同一准确制品真实模型调用四个 lsp 操作，检查精确源文件位置、跨文件引用、类型／接口及新内容读入；验证无结果与工作区外读取拒绝。补充真正服务器的复用、退出后重建、取消与 provider 销毁／进程回收；不以伪造服务器取代正常语义测试，故障夹具只证明其明确故障场景。覆盖安装保留旧会话；临时 bundle／配置／锁文件／凭据与自建目录恢复。记录全部失败、测试源码和 HAP 摘要，必要回归通过后推送。

非目标：一次性承诺所有语言服务器或所有项目规模、系统 PTY、Phone Use、内核隔离、任意原生 npm addon；现有工具和权限契约继续保留。

状态：LSP 0.4.35 节点已实现并通过11组模拟器检查，具体制品、来源、失败和限制见下文及证据。整体能力补齐目标仍在推进。

## 项目加载阻塞复现与修复（进行中）

原布局实际 lsp 调用超过上游60秒超时。独立 stdio 客户端驱动同一真实 TypeScript language server，tsserver 日志停在监听整棵 DSH node_modules；25秒诊断截止没有语义回复，记录失败而非通过。真实 Node fork IPC 对照在约1.37秒完成往返和退出，不能归因为 IPC 不可用。

将完全相同的 TypeScript 6.0.3 文件复制到独立工具链目录后，实际 definition 返回源文件第1行第17列，6.774秒；保留原通配 tsconfig 的复核为8.722秒，均正常 shutdown、exit0。构建因而在 release/toolchains/lsp/node_modules 中增加由同一锁文件生产包逐字节复制的编译器，不删 DSH 原依赖，不禁用工作区监听，不改上游服务器。正常 bundle 指向该副本；额外压缩体积及正式工具结果仍待构建验收。

测试差异：标准库位置断言调整为实际独立工具链物理路径，继续严格检查 Host 可读取的精确 lib.es5.d.ts 位置和源行，没有移除语义要求。新增 Node IPC 夹具仅用于排除进程通信故障，不冒充 LSP 语义测试。候选改为正式 @mobile-harness/lsp bundle，工厂配置只迁移一次；用户随后禁用不得被启动流程重开。
