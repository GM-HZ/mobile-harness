# 鸿蒙 Forge 工作树恢复

以 Mobile Harness 98b4fc4 和已安装的 0.4.36 为基线。此前实际验证过工作树创建、cwd 切换、重启、脏目录保留和干净工作树归档。此次补验 Forge 的官方恢复 RPC，以及工作树恢复过程的取消。

使用测试专有仓库与正式 Forge bundle。会话通过已有权限命令批准夹具执行，记录分支和基准提交。在工作树上另做一次提交并留下未提交文件，确认重新检出使用分支最新提交，原工作区字节保持。删除分支后应以记录的基准提交重建。

为复现取消，在 Git 已建立真实 worktree 注册之后，只延迟夹具仓库中的最终 reset 命令，使用实际 Harmony 子进程 provider 及原取消信号。断开已鉴权的 HTTP 请求后检查实际进程回收、原分支与部分检出目录保留、日志没有错误标记为 restored，并重新执行恢复。夹具恢复 profile、锁文件与启动配置的原始字节。

测试不覆盖 GitHub 登录、远端 PR 或 Forge 客户端视觉。测试也发现 0.4.36 的安装目录遗漏官方 Forge。

0.4.37 在安装锚登记官方 Forge、Ralph、会话搜索和独立工作树，沿用各自的上游展示规则，均默认关闭。构建核对这四项是锁定 DSH 自身的直接依赖，已安装版本匹配且存在官方 bundle patch。ZIP 成员名单相同，大小和 CRC 变化仅在安装锚清单。

三组模拟器检查通过。通过 PluginManager 启停并重启后核对实际插件状态，Forge 使用真实提交验证现有分支与缺失分支恢复，在受管检出阶段取消后核对进程回收及重试。另通过 LSP 开关与崩溃恢复回归。0.4.36 的两次失败分别源于测试少算重试事件、重启后取消了已结束的初始化会话，保留原结果与测试修正。[制品、日志与审计](../evidence/emulator-worktree-catalog-0.4.37.json)
