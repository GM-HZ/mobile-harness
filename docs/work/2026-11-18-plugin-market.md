# 鸿蒙插件市场与更新回滚

基线为 Mobile Harness 9ba560f、应用 0.4.39 和 DSH RC.4。上轮交付 DeepSeek 会话导入及续接，已推送源码与实测证据。此次登记自带的官方插件市场，遵循其默认关闭策略。

在独立 Phone 模拟器用回环索引和 npm 仓库提供自建的纯 JS 包。经过官方 setIndexes、search、installBundle、listVersions、updateBundle 和 removeBundle，验收索引校验、分页、安装来源、依赖、启用状态、失败恢复与脚本策略。失败用例分别覆盖安装前拒绝和安装后激活异常，随后用真实工具断言旧版本重新可用。回滚不改用户的其他插件。使用独立夹具名，锁文件及配置恢复为原字节。

不向公共仓库发包。Git 来源升级、公共索引和市场长说明若未实测则保留在证据边界。

0.4.40 通过 Worker 索引校验、分页、真实 pnpm 安装、依赖运行和不兼容版本拒绝。更新 1.1.0 时 DSH 明确报告 module-comparison，重启后模型工具返回新版本。接着候选的全新入口触发真实激活失败。回滚却丢失重启前的仓库来源，旧包请求去了公共 npm，收到 404，并随后超时。这条失败记录说明市场来源必须绑定跨重启回滚。

0.4.41 在受管 profile 为成功安装留下按包名和已装版本核对的仓库来源，复用现有包管理适配层和上游更新事务。记录使用应用私有目录、原子写入，移除包时删除。注册表 URL 中的账号、密码、查询串和片段均不持久化。既有未记录的安装沿用上游仓库选择，新安装或实际更新后才有精确来源记录。加载模块无法比较时遵循 DSH 的重启返回。

0.4.41 模拟器已观察到新进程读取仓库来源、1.2.0 激活失败、1.1.0 恢复，以及模型再次调用 1.1.0 工具成功。旧断言要求回滚启动只能出现在最后一个位置，重启重复启动 1.1.0 后退出 1。现在核对完整版本顺序与失败候选只启动一次，继续验收卸载和来源清理。
