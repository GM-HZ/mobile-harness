# 鸿蒙原生 Office 执行

2026-11-18，API 26 ARM64 Phone 模拟器。0.4.32 使用同一已锁定的鸿蒙 Node 24.14.1 与官方 LibreOffice Kit 0.2.3；未重新编译 Node，也未更换文档引擎。

## 从失败到原生执行

0.4.31 的真实 `office_convert` 首先返回没有可用字体。Office Skill 已加载，但这不构成转换成功。将系统字体提供给同一 Kit 后，手机随包 Linux Node 的最小 WASM 返回 42，独立 DOCX 转换成功，耗时约 96.5 秒。接入普通 App 后，PRoot 路径完成 Word PDF、页面图像和 Excel 重算，但同一份官方 PPTX 夹具超过 195 秒未返回，由宿主终止。

相同 PPTX 和同版本 WASM 引擎在电脑约 1.3 秒完成。进一步用独立 HAP 验证：鸿蒙原生 Node 不加 `--jitless` 时，WASM 返回 42、内置 TypeScript 擦除后返回 42，原生 fetch 从该子进程自己的 HTTP 服务取得 200。Node 子进程退出 0，N-API 观察总时长 364 ms；脚本内部报告 172 ms。这只证明当前模拟器的这条路径可用，不能推断所有鸿蒙设备和签名配置均支持 JIT。

## 保留上游职责的适配

上游 OfficeKit 提供源授权、排队、输入限额、缓存、输出验证和生命周期。配置允许字体、限额及 engine package 定位，没有公开的转换器进程启动器入口。本工程保留原服务，仅在模块解析时将该服务对 `@deepseek-ai/libreoffice-kit` 的消费定向到实现其公开 `Converter` 接口的适配器。其他消费者和 npm 包内容不改写。

Office worker 从 Host 加载 Node 之前创建的进程管理器派生，避免从已运行的 V8 进程 fork 后重启 Node。入口固定为随包脚本，清空继承环境并设置应用自己的 HOME、TMPDIR，关闭多余描述符；只接收能力探测、初始化、转换、渲染、重算、取消与销毁消息。原生启动先执行最小 WASM，成功后再导入准确的锁定 Kit；不支持的设备在接收文档任务前选择已有 Guest 执行路径。进程管理器的容量错误不通过回退绕过。

主 Host 和受限 PTC 继续使用原配置。Office 是处理授权文档的受信任组件，不向模型开放任意 JIT 代码执行。其进程依赖鸿蒙 App 边界和上游输入协议，不宣称使用 PTC 文件中介实现了完整工作区内核沙箱。

原生 worker 直接使用系统字体，不向包中复制系统字体。Guest 路径将系统字体映射到其字体目录。Host 的 Office scratch 位于应用运行时的 tmp 目录；路径在 Host 与 Guest 间明确转换，图像路径须落在本次输出目录内。输出仍由上游按会话归属保留与清理。

## 验证结果

| 操作 | 先前 Guest 引擎时间 | 原生引擎时间 |
| --- | --- | --- |
| DOCX → PDF | 42.8 秒 | 2.6 秒 |
| 页面图像 | 32.6 秒 | 2.0 秒 |
| XLSX 公式重算 | 55.4 秒 | 2.0 秒 |
| PPTX → PDF，同一夹具 | 超过 195 秒后终止 | 2.0 秒 |

这些是本轮各次执行记录，不是控制缓存状态的通用性能保证；不包含模型来回耗时。原生 Word 页面附件已通过实际附件接口读取并目视确认原始标记。Excel 结果 ZIP 回读保留公式，将缓存值从 0 更新到 42。重复 DOCX 转换命中上游 Host 缓存，没有再次派发引擎操作。损坏文档被拒绝。

真实 `session/cancel` 在操作在途时被调用，约 139 ms 观察到回合中止、引擎结束和 scratch 清理，同一会话随后继续转换成功。独立 fixture-owned OfficeKit 通过空闲／在途销毁、读者取消、100 ms 超时、helper 被杀后的新请求恢复；销毁后拒绝新请求，所有新建 helper 都验证已回收。

已复现并修复旧连接的故障：进程被终止后，原转换器仍被服务 slot 持有。现在稳定的 Converter 在后续新请求时重建连接，不自动重放失败操作。Native 加速后，第二轮模型请求可能晚于原操作完成；生命周期测试改为在同一次工具调用中观察到真实请求在途后立即触发销毁／取消，仍要求中止结果和全部清理。

准确源码、制品、命令、失败尝试及回归范围见 [0.4.32 证据](../evidence/emulator-office-0.4.32.json)。真机结果仍待验证。
