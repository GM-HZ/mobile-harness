我把我们这几次关于 手机原生 Harness、Personal Agent、移动端 AI、浏览器自动化、跨设备执行以及未来 AGI 形态 的讨论整合成一份长期产品愿景。

重点不是当前怎么实现，也不是缩小成一个 MVP，而是明确：我们相信未来会发生什么、为什么这个方向成立，以及最终要创造什么产品。

# Mobile Harness：未来产品愿景与技术预期

**核心愿景：手机 Harness，实现你所想的一切。**

**英文定位：Whatever you imagine, your Agent makes it happen.**

## 一、我们对未来的核心判断

我们认为，未来个人计算设备的交互方式将发生根本性变化。

过去几十年，智能手机的核心模式一直是：

**用户产生需求 → 寻找 App → 打开 App → 学习和操作界面 → 完成任务。**

但随着大语言模型、Agent 和 Harness 技术的发展，未来的模式有机会转变为：

**用户表达意图 → Agent 理解目标 → Harness 自主规划与执行 → 用户获得结果。**

这不是简单地增加一个语音助手，而是让用户逐渐摆脱对具体软件操作流程的依赖。

未来人们可能不再需要知道一件事情应该由哪个 App 完成、应该点击哪些按钮、应该执行哪些步骤。

用户只需要知道自己想要什么。

我们的目标，就是构建这样一个真正具备执行能力的个人智能代理。

## 二、为什么我们认为手机原生 Harness 是一个重要机会？

### 1. 手机已经具备运行 Harness 的硬件基础

手机厂商正在不断增强端侧 AI 算力，并尝试部署数十亿参数规模的本地语言模型。

而 Harness 本身并不需要承担大模型推理。

Harness 的核心工作包括：

- Agent Loop 与任务调度
- Session 和上下文管理
- Tool / Skill / Plugin 调用
- 任务拆解、并发执行与状态恢复
- 记忆管理与权限控制

这些工作的基础计算开销通常远小于本地大模型推理。

因此，我们判断：

**手机运行一个原生 Harness，在硬件资源层面已经具有现实可行性。**

而且模型可以运行在云端，本地 Harness 只负责调度和执行。

未来随着本地模型不断发展，Harness 也可以动态选择本地或云端推理。

当然，持续视觉识别、浏览器自动化和高频执行任务仍可能产生较高的电量和资源开销。

### 2. 手机的用户规模和使用频率提供了更广阔的市场

相比电脑，智能手机覆盖更多普通消费者，使用场景更加日常化、碎片化。

大量手机操作实际上是低复杂度、重复性的，例如：

- 查询、搜索、整理信息
- 购物、订票、预约服务
- 处理消息与邮件
- 日程、提醒、生活管理
- 管理照片、文件和内容
- 跨平台搬运与整理信息

这些任务本身并不需要用户亲自操作每一个步骤。

因此，手机端 Agent 的潜在价值，不仅来自单个任务节省多少时间，还来自它每天能够替用户完成多少次操作。

### 3. 浏览器已经覆盖了大量数字服务

我们特别关注一个事实：

**大量原本由 App 完成的事情，也可以通过浏览器完成。**

浏览器提供了一个非常广泛的服务入口，包含购物、办公、社交、信息查询、内容管理和在线业务。

Agent 可以通过浏览器操作网页，执行复杂的跨网站任务。

浏览器的 DOM、结构化页面信息和网页接口，还能够降低部分自动化任务对视觉模型的依赖。

这意味着：

即使暂时不具备所有手机 App 的操作权限，Harness 也已经拥有一个覆盖面很广的执行环境。

但浏览器只是 Harness 的一种能力，而不是产品边界。

**我们的最终目标仍然是让 Harness 能够操作整个手机，并进一步连接用户的所有数字设备。**

## 三、手机原生 Harness 的最终产品形态

我们希望创造的是一个具有以下能力的 Personal Agent。

### 1. 通用任务执行

用户可以通过自然语言或语音提出目标。

Agent 自动理解需求、制定计划、选择工具、执行操作，并验证结果。

任务既可以非常简单，也可以极其复杂。

从设置一个提醒，到长期协助经营一个网店，都应该属于同一个任务执行体系。

### 2. 全面的手机操作能力

Harness 不应该被限制在某种特定的执行工具中。

未来应当逐渐覆盖：

- Browser Use：网页操作与在线服务
- App / Computer Use：图形界面与应用交互
- Native Tools：手机系统原生能力
- API / MCP：直接调用结构化服务
- Skills / Plugins：动态扩展专业能力

我们的长期目标是覆盖手机上绝大多数可自动化的数字操作。

这里的技术难点不只是执行能力，还包括操作系统权限、应用沙箱、安全策略和用户授权。

### 3. 长期记忆与个人理解

Agent 不应该是一个每次打开都需要重新认识用户的聊天机器人。

它需要持续理解用户的：

- 使用习惯、偏好和长期目标
- 日常工作和生活安排
- 历史任务与已有决策
- 常用工具、设备与服务
- 正在进行的长期项目

随着使用时间增加，它应该越来越了解用户，减少重复沟通。

记忆也需要支持用户查看、修改、删除及控制使用范围。

### 4. 持续运行与主动服务

Agent 不应该只能等待用户发送指令。

它可以在获得授权后，主动完成周期性或条件触发的任务，例如检查待办、监控重要事项、整理信息、到时提醒。

从技术上说，我们追求的不是 CPU 永久执行，而是：

**Agent 在逻辑上持续存在，任务可以暂停、恢复、继续，状态不会因为进程退出而丢失。**

手机操作系统允许时正常执行；不允许后台长期运行时，利用系统调度、持久化任务和其他设备协作维持服务连续性。

### 5. 跨设备统一执行

手机是最自然的交互入口，但它不应该是 Agent 的能力边界。

未来的 Personal Agent 可以连接：

- 手机
- 个人电脑
- 家庭服务器
- 云端计算资源
- 外部应用和在线服务

用户在手机上提出一个任务，Harness 可以判断应该在哪里执行。

例如用户说：

“把我昨天电脑上没有完成的工作继续处理，整理好后发给客户。”

手机 Agent 可以连接电脑端 Harness，恢复任务状态，调度执行，再向用户反馈结果。

对于用户来说，这仍然是同一个 Agent。

### 6. 自主扩展执行能力

我们希望 Harness 具备持续扩展的能力。

遇到新的需求时，可以发现、安装、配置或者在受控环境下生成合适的 Skill 与工具。

未来的智能代理不应该拥有固定且封闭的能力清单。

**它应该具有不断扩展能力边界的机制。**

## 四、我们预期未来会出现的产业变化

### 趋势一：用户使用 App 的方式发生改变

大量工具型 App 的操作可能逐渐被 Agent 接管。

用户依然使用这些服务，但不一定再需要频繁进入 App 的界面。

App 从用户直接操作的对象，部分转变为 Agent 调用的服务。

### 趋势二：软件逐渐面向 Agent 提供能力

今天的应用主要围绕人类用户设计 GUI。

未来可能有更多服务主动提供 API、Agent Tool、MCP 或类似的标准化执行接口。

软件将同时面向两类使用者：

人类用户，以及代表人类完成任务的 Agent。

### 趋势三：手机成为个人 Agent 的主要入口之一

手机天然具备随身携带、语音交互、身份认证、通知提醒和生活场景覆盖等优势。

我们预期，这些特征可能让手机成为个人智能代理最重要的日常入口。

而高性能电脑和云端，则承担更复杂的计算与执行任务。

### 趋势四：模型与执行系统逐渐解耦

未来的用户不一定关心自己使用的是哪个模型。

不同任务可以由不同模型完成。

Harness 负责根据任务难度、延迟、成本、隐私要求和可用资源选择合适的模型。

模型是智能资源，Harness 才是维持用户任务连续性的执行基础设施。

### 趋势五：Agent 从工具转向持续性的个人服务

传统软件通常是用户主动使用。

而未来的 Agent 可能具备持续记忆、长期目标、主动服务和跨设备执行能力。

它不再只是一个完成单次任务的工具，而是持续为用户提供服务的个人代理。

## 五、我们的长期技术架构预期

总体采用：

**Personal Agent + Harness Core + Execution Runtime + Model Routing**

### Personal Agent 层

负责用户交互、长期记忆、个人偏好、目标管理和主动服务。

### Harness Core 层

负责 Agent Loop、任务规划、Session、上下文管理、子任务调度、状态恢复、结果验证和权限管理。

这是整个产品的核心。

### Execution Runtime 层

由浏览器、移动端原生工具、图形界面操作、桌面端 Harness、云端执行环境和插件体系共同组成。

不同操作系统可以使用不同的 Runtime，但尽量保持统一的任务协议。

### Model Routing 层

支持多个云端模型和本地模型，根据成本、能力、速度和隐私要求灵活调度。

**未来模型可以替换、设备可以更换、插件可以扩展，但用户的个人 Agent、记忆和任务体系应该保持连续。**

## 六、未来的发展阶段

| 阶段   | 目标              | 主要变化                 |
| ---- | --------------- | -------------------- |
| 第一阶段 | 可用的个人 Harness   | 从对话走向真实任务执行          |
| 第二阶段 | 通用手机 Agent      | 广泛连接浏览器、App 与系统能力    |
| 第三阶段 | 跨设备个人 Agent     | 手机、电脑、云端统一调度         |
| 第四阶段 | 持续性个人智能代理       | 长期记忆、主动服务、自主扩展       |
| 长期愿景 | Mobile AGI 产品形态 | 用户的大部分数字化意图能够直接转化为结果 |

这些阶段描述的是能力演进，并不意味着必须严格按顺序开发。部分能力可以并行建设。

这里的 Mobile AGI 是我们的产品愿景称谓，不等同于已经实现严格意义上的通用人工智能。

## 七、需要正视的不确定性

我们对长期方向有较强信心，但仍有几项关键假设需要验证。

**技术上：** 手机原生 Harness 的资源开销是否足够低，长时间任务是否能够可靠恢复，复杂网页和 App 自动化的成功率是否足够高。

**平台上：** Android、鸿蒙和 iOS 会开放多少能力给第三方 Agent，是否能够建立稳定、合规的执行机制。

**用户上：** 人们是否真的愿意把大量操作交给 Agent，以及它能否在速度、成功率和成本上持续优于手动操作。

**商业上：** 操作系统厂商会持续集成类似能力，独立 Personal Agent 必须依靠跨平台、记忆、执行可靠性、开放生态和用户信任形成差异化。

尤其是涉及付款、发送消息、删除内容和敏感数据的操作，需要可审计的执行记录与明确的授权边界。

## 八、最终衡量标准

我们不应该单纯以支持多少模型、多少插件、多少 App 来衡量产品成功。

更重要的是：

1. 用户想做的事情，有多少能够真正完成？
2. 用户完成任务，需要亲自参与多少步骤？
3. Agent 能否长期可靠地执行、恢复和验证任务？
4. Agent 是否随着长期使用，越来越理解用户？
5. 用户是否开始自然地优先向 Agent 提出需求，而不是打开 App？

这些才是判断我们是否接近目标的核心指标。

## 九、我们的最终愿景

我们不是为了把大模型装进手机。

也不是为了给手机增加一个聊天窗口。

我们相信，随着智能模型、Harness、工具生态和设备计算能力的发展，人类使用数字设备的方式将逐渐从**亲自操作软件**转向**委托智能代理完成任务**。

手机拥有庞大的用户基础、天然的个人属性和广泛的生活场景，因此可能成为这次转变最重要的载体之一。

我们希望构建的，是一个原生运行、长期存在、理解用户、具备执行能力、可以连接整个数字世界的个人 Agent。

它不仅能够回答问题，更能够真正完成事情。

**我们的长期目标不是让用户学会使用更智能的软件，而是让软件能够理解并执行用户的想法。**

**Mobile Harness — 想到，即做到。**

我认为这里还需要明确一个战略判断：我们真正想建立的长期资产，不是某个手机 App，而是一个持续存在、跨设备、可扩展的个人 Agent 执行体系。

手机只是最重要的入口。Harness 是核心。模型是可以替换的智能资源，Browser、App、电脑和云端是执行资源。

这样，无论未来 GUI 怎么发展、手机系统怎么变化，甚至模型供应商怎么变化，我们的目标都保持一致：尽可能让用户的意图直接转化为现实的数字化结果。
