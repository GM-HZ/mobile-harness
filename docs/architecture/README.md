# Architecture & adaptation system

This directory owns the **adaptation and gate architecture** of Mobile Harness:
how we layer meaning onto upstream DeepSeek Harness, how we track upstream,
and how a change is proven before it reaches `main`.

- [2026-11-20 adaptation and gates plan](2026-11-20-adaptation-and-gates-plan.md) — current plan, patch layers, upstream bumping, gate tiers, RSI loop.
- `adaptation/manifest.json` — machine-readable inventory of every adaptation surface (generated by `scripts/adaptation/inventory.py`).
- `versions.lock.json` — pinned upstream graph (DSH release, npm lock, submodules, build inputs).
- `gates/registry.json` — gate tiers and the commands that make them up.
- `variants/` — store/self/lab build shapes with HAP assertions (`variant_check.py`).
- `docs/architecture/seams/` — contracts for each fragile upstream touchpoint (see [seams README](seams/README.md)).
- [compat-layer.md](compat-layer.md) — inventory and decisions for the HarmonyOS compatibility modules.

Rules of thumb:

1. Prefer an upstream extension seam (plugin, bundle, profile patch, provider) over patching upstream code.
2. Every patch or runtime replacement must be listed in `adaptation/manifest.json` with an owner, an upstream touchpoint and a gate.
3. No new adaptation lands without a gate that fails when it regresses.
4. Upstream bumps are rehearsed by `scripts/adaptation/verify.py` + the gate suite before merge.
